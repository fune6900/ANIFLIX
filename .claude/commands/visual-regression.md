Playwright MCP を使用して ANIFLIX の視覚的整合性の自動検閲を行う。図案のメイド（Designer サブエージェント）を起動し、以下の手順を厳守すること。

## 対象

- 引数 $ARGUMENTS に検査対象の URL またはページパスを指定する。
- 未指定の場合は `http://localhost:3000` を起点に主要ページを巡回する:
  - `/`（ホーム）
  - `/search?q=進撃`
  - `/anime/1429`（例: 進撃の巨人）
  - `/voice-actors`
  - `/browse/airing`
  - `/browse/genres`
- カンマ区切りで複数 URL 指定可能。

## 手順

### Phase 1: ベースライン確認（デスクトップ）

- `mcp__playwright__browser_navigate` で対象 URL へ遷移する。
- `mcp__playwright__browser_take_screenshot` でデスクトップ（1280x800）のスクリーンショットを取得する。
- `mcp__playwright__browser_snapshot` でアクセシビリティツリーと DOM 構造を取得する。

### Phase 2: インタラクティブ・ステート検証

各ページで以下の状態を順に操作し、その瞬間のスクリーンショットを撮影する。

1. **通常状態 (Default)**: ページ初期表示をキャプチャ
2. **ホバー状態 (Hover)**:
   - Navbar: ナビリンクのアンダーラインなし → ホバー時の色変化
   - ContentRow カード: 800ms 後にプレビューポップアップ
   - Hero: 左右矢印が `opacity-0 hover:opacity-100`
3. **フォーカス状態 (Focus)**: Tab でフォーカス移動、検索ボックス・カードへの focus ring を確認
4. **入力状態 (Input)**: Navbar 検索ドロップダウン、`/search` フォーム
5. **エラー状態 (Error)**: TMDb 不達時のエラーメッセージ表示
6. **ローディング状態 (Loading)**: 検索デバウンス中のスピナー、エピソード読込中

### Phase 3: レスポンシブ・ストレステスト

`mcp__playwright__browser_resize` で以下のビューポートに順次リサイズしてスクリーンショットを取得する。

| デバイス      | 幅   | 高さ |
| ------------- | ---- | ---- |
| iPhone SE     | 375  | 667  |
| iPhone 14 Pro | 393  | 852  |
| iPad          | 768  | 1024 |
| Laptop        | 1280 | 800  |
| Full HD       | 1920 | 1080 |

各解像度で以下を確認する:

- **モバイル**: BottomNav が表示される / Navbar 右側がハンバーガー化 / ContentRow カードが小さくなる（`w-[120px]`）
- **タブレット**: ナビが横並び表示に / グリッドが 4 列
- **デスクトップ**: グリッドが 5 列
- **Full HD**: 1920px コンテナで両端に余白
- テキストが溢れていないか（`line-clamp` が効いているか）
- ボタン・リンクが重なっていないか
- 画像のアスペクト比（ポスターは 2:3、バックドロップは 16:9）が崩れていないか
- Hero の `text-3xl sm:text-4xl md:text-5xl …` の段階が破綻していないか

### Phase 4: UX 動線追跡

主要フロー（ページの性質に応じて実行）を実際に操作し、各ステップの応答時間を計測する。

1. **アニメ検索**: 検索アイコンクリック → ドロップダウン表示 → 入力 → 候補表示までの時間
2. **アニメ詳細**: カードクリック → 詳細ページ表示 → トレーラー再生までの時間
3. **声優詳細**: 一覧 → カードクリック → 出演作グリッド表示までの時間
4. **無限スクロール**: `/browse/movies` で末端到達 → 追加読込が走るまでの時間

`mcp__playwright__browser_evaluate` で `performance.now()` を使用し、操作間隔（ms）を計測する。

### Phase 5: コンソールエラー確認

- `mcp__playwright__browser_console_messages` でコンソール出力を取得する。
- 特にチェック: 画像 404、TMDb 429、React hydration mismatch、`next/image` の警告

## 注意

- 開発サーバーが起動していない場合は `npm run dev` の実行をマスターに促すこと。
- 「なんとなく崩れている」という曖昧な報告は不可。ズレは px 単位、遅延は ms 単位で報告すること。
- `mcp__playwright__browser_evaluate` で CSS の計算値（`getComputedStyle`）を取得し、設計値との乖離を数値で示すこと。
- スクリーンショットで視認できた問題は、DOM inspection で根本原因（どの Tailwind クラス・CSS プロパティが原因か）まで特定すること。
- 修正提案は「色を調整しましょう」のような曖昧なものは不可。`className` の変更、`style` プロパティの具体値まで落とし込むこと。
- 複数 URL が指定された場合は、全 URL に対して Phase 1〜5 を実行してから総合報告すること。
- 撮影したスクリーンショットは検証後に必ず削除する（`@.claude/rules/dev-flow.md` Step 7-1）。
